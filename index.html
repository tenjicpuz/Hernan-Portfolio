Featured project

Portfolio platform

A public site anyone can read, and a private dashboard where only I can publish certificates, links and content.

A full-stack case study: static front end, Supabase back end, and security rules enforced in the database itself.

BrowserPublic site and admin dashboard. Vanilla JavaScript, no framework.
loads pagesreads repositoriessigns in, reads and writes data
GitHub PagesStatic hosting and deployment from the main branch.
GitHub REST APILive repository list and profile summary, cached for 15 minutes.
SupabaseAuth, PostgreSQL and Storage behind row-level security.
access rules / anyone can read published data. only the owner account can insert, update or delete.
Problem
A static site can't manage its own content. I wanted to publish certificates and links safely without editing code each time.
Back end
Three PostgreSQL tables (certificates, contact links, portfolio content) with length and format constraints, an index for ordered reads, and a storage bucket limited to PDF, PNG, JPG and WEBP files up to 10 MB.
Security
Row-level security on every table and storage bucket, one owner check shared by all write policies, public sign-ups disabled, and HTTPS-only file URLs enforced in the database. In the browser, database text is escaped and link schemes are validated before rendering. No secret key is shipped.
Quality
One GitHub request feeds both the summary and the project list, with session caching. Lazy-loaded images, keyboard-friendly navigation, responsive layouts, a print stylesheet and schema.org structured data.
My role
Sole developer: design, front end, database schema, policies and deployment.
